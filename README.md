# Telegram-бот Ensi Cloud (RAG) — каркас

Бот-ассистент по сайту [ensi.cloud](https://ensi.cloud/): отвечает на базовые вопросы
по продуктам, тарифам, кейсам и внедрению, предлагает записаться на бесплатный
экспресс-аудит и отправляет уведомления менеджерам.

Стек: **Python 3.11+**, **aiogram 3**, **SQLite**, гибридный поиск **BM25 + эмбеддинги**,
любой **OpenAI-совместимый** LLM API (OpenAI, DeepSeek, OpenRouter, vLLM, Ollama).

---

## Что уже умеет

- **RAG-ответы** по материалам сайта: находит 3–5 релевантных фрагментов и генерирует
  ответ строго по ним, со ссылками на источники.
- **Работает без LLM-ключа**: пока `LLM_API_KEY` пуст, бот отдаёт выдержки из сайта.
  Без ключа также остаётся лексический поиск (BM25), с ключом — ещё и векторный.
- **Экспресс-аудит**: пошаговая заявка (имя → сайт → контакт → комментарий → подтверждение),
  запись в БД и уведомление менеджерам.
- **Уведомления менеджерам**: новый пользователь, «изучает бота» (с кратким списком
  запросов), просьба связаться, новая заявка на аудит. Под каждым уведомлением — кнопка
  **«📜 История запросов»**: менеджер видит все вопросы пользователя с датами и его заявки.
- **Админка**: статистика, последние заявки, состояние базы знаний, тест уведомлений.
- **Разные меню команд**: обычные пользователи видят только базовые команды, менеджеры —
  ещё историю запросов, админы — полный служебный набор. Меню ставится персонально
  через `BotCommandScopeChat` и не светится у клиентов.
- **Инжест сайта**: краулер с `sitemap.xml`, очистка Tilda-разметки, нарезка на чанки,
  эмбеддинги, инкрементальное обновление по хешу страницы.
- Всё, что нужно для старта: `.env.example`, Dockerfile, тесты.

## Структура

```
bot/
  main.py              # точка входа, сборка зависимостей, polling
  commands.py          # меню команд: публичное, менеджеры, админы
  config.py            # настройки из .env
  db.py                # SQLite: пользователи, события, заявки, вопросы, чанки
  llm.py               # клиенты chat/embeddings (OpenAI-совместимые)
  notifications.py     # отправка уведомлений менеджерам (ID из .env)
  keyboards.py         # inline-клавиатуры
  dialogue.py          # память диалога (последние N пар)
  texts.py             # все тексты бота
  prompts.py           # системный промпт RAG
  formatting.py        # HTML/экранирование/обрезка
  services/analytics.py# события «зашёл», «что искал» + антиспам
  services/access.py   # кто менеджер/админ (доступ к истории и админке)
  handlers/
    start.py           # /start /help /reset /id
    audit.py           # FSM-заявка на экспресс-аудит
    chat.py            # свободные вопросы → RAG
    menu.py            # кнопки «продукты», «менеджер»
    history.py         # история запросов пользователя для менеджеров
    admin.py           # /stats /leads /knowledge /test_notify
  rag/
    crawler.py         # обход сайта, robots.txt, извлечение текста
    chunker.py         # нарезка текста на чанки
    tokenizer.py       # токенизация + лёгкий стеммер
    bm25.py            # лексический поиск
    store.py           # гибридный индекс (RRF)
    retriever.py       # поиск + генерация ответа
    ingest.py          # CLI-инжест сайта
tests/                 # тесты чанкера, поиска и БД (без сети)
data/bot.sqlite3       # локальная БД (создаётся сама, в git не попадает)
```

## Быстрый старт

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

copy .env.example .env
# откройте .env и заполните BOT_TOKEN (от @BotFather)

# 1) собрать базу знаний с сайта
python -m bot.rag.ingest --max-pages 60

# 2) запустить бота
python -m bot
```

Linux/macOS: `source .venv/bin/activate`, `cp .env.example .env`.

Проверка без Telegram:

```powershell
pip install -r requirements-dev.txt
pytest
python -m bot.rag.ingest --dry-run --max-pages 5
```

## Куда вписать менеджеров (главное)

1. Менеджер открывает бота и отправляет `/id` — бот покажет его Telegram ID
   (команда убрана из меню, но работает).
2. Администратор вписывает эти ID в `.env`:

   ```env
   MANAGER_CHAT_IDS=123456789,987654321
   ADMIN_IDS=123456789
   ```

   Можно указать ID группы (отрицательное число) — бот должен быть в ней.
   Для супергруппы с темами дополнительно задайте `MANAGER_TOPIC_ID`.

3. Перезапустите бота и проверьте: `/test_notify` (доступно администратору).

Пока `MANAGER_CHAT_IDS` пуст, уведомления **не отправляются, но не теряются**:
каждое событие пишется в таблицу `events` (причина — `notify_skipped`).

## Наполнение и обновление базы знаний

```powershell
python -m bot.rag.ingest                  # сайт + sitemap.xml
python -m bot.rag.ingest --reset          # пересобрать с нуля
python -m bot.rag.ingest --max-pages 100  # глубже
python -m bot.rag.ingest --no-embeddings  # только BM25 (без затрат на API)
python -m bot.rag.ingest --force          # переиндексировать всё
python -m bot.rag.ingest --dry-run        # посмотреть, что соберётся
```

- Неизменившиеся страницы пропускаются по хешу.
- Если страница была собрана без эмбеддингов, повторный запуск с ключом
  досчитает векторы.
- После инжеста перезапустите бота — индекс читается при старте.
- Регламент: обновлять раз в сутки/неделю по cron или вручную после правок сайта.

Полезные ключи `.env`: `SITE_BASE_URL`, `SEED_URLS` (свои стартовые URL через запятую),
`RAG_TOP_K`, `RAG_MIN_SCORE`, `DB_PATH`.

## Настройки (.env)

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `MANAGER_CHAT_IDS` | кому слать уведомления (через запятую) |
| `MANAGER_TOPIC_ID` | тема в супергруппе (опционально) |
| `ADMIN_IDS` | доступ к `/stats`, `/leads`, `/knowledge`, `/test_notify` |
| `NOTIFY_ON_SIGNUP` / `NOTIFY_ON_VIEW` | включают уведомления о заходе/просмотре |
| `VIEW_NOTIFY_COOLDOWN_HOURS` | антиспам на уведомления «изучает бота» |
| `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | провайдер и модель |
| `EMBEDDING_MODEL`, `EMBEDDINGS_ENABLED` | векторная часть поиска |
| `RAG_TOP_K`, `RAG_MIN_SCORE` | сколько фрагментов брать и порог близости |
| `RATE_LIMIT_SECONDS`, `HISTORY_TURNS` | антифлуд и память диалога |
| `CONTACT_TELEGRAM`, `CONTACT_PHONE` | контакты в ответах |

Примеры провайдеров:

```env
# OpenAI
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini

# DeepSeek
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

# локальный Ollama
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=llama3.1
EMBEDDING_MODEL=nomic-embed-text
```

> Эмбеддинги должны быть доступны по тому же `LLM_BASE_URL`. Если провайдер их не
> отдаёт — поставьте `EMBEDDINGS_ENABLED=false`, бот продолжит работать на BM25.

## Как работает ответ

1. Вопрос логируется в `query_log` (это и есть «что искал» для уведомлений).
2. Гибридный поиск: BM25 по названию страницы + тексту, плюс косинус по эмбеддингам;
   результаты объединяются через Reciprocal Rank Fusion.
3. Топ-`RAG_TOP_K` фрагментов уходят в промпт (`bot/prompts.py`) с жёстким правилом
   «отвечай только по контексту, не выдумывай цены и сроки».
4. Ответ приходит в HTML, под ним — кнопки «Экспресс-аудит», «Менеджер» и ссылки
   на страницы-источники.
5. Если ничего не найдено — бот честно говорит об этом и предлагает аудит/менеджера.
   Если LLM недоступна — отдаёт выдержки из сайта с пометкой.

## Уведомления менеджерам

| Событие | Когда | Что внутри |
|---|---|---|
| `signup` | первый `/start` | имя, @username, ID, источник (deep-link) |
| `view` | задал вопрос (не чаще cooldown) | последние 3 запроса, сколько вопросов сегодня |
| `contact_request` | кнопка «Связаться» (дедуп 30 мин) | последние запросы |
| `audit_request` | отправлена заявка | имя, сайт, контакт, комментарий, что искал, номер заявки |

Формат — HTML-сообщение с кликабельными кнопками «Написать» и **«📜 История запросов»**.
Все события также лежат в SQLite: `events`, `leads`, `query_log`.

### История запросов пользователя

- Кнопка **«📜 История запросов»** под любым уведомлением (в личке или общей группе).
- Команда `/history <id>` или `/history @username` — для менеджеров и админов
  (`MANAGER_CHAT_IDS` + `ADMIN_IDS`). Показывает визиты, количество вопросов,
  последние заявки и запросы с датами, по 10 на страницу с навигацией.
- Команда `/id`, которую менеджер использует при настройке, не показывается в меню
  и в `/help`, чтобы не вызывать вопросов у обычных пользователей.

## Админ-команды

- `/stats` — пользователи, вопросы, заявки, состояние индекса, включена ли LLM.
- `/leads [N]` — последние заявки.
- `/knowledge` — какие страницы в базе знаний.
- `/test_notify` — проверка, что уведомления доходят до всех менеджеров.
- `/history <id|@username>` — история запросов пользователя (менеджеры и админы).
- `/id` — показывает Telegram ID; специально **не выводится в меню и в `/help`**,
  чтобы не отвлекать обычных пользователей. Нужен только при настройке уведомлений.

### Меню команд для сотрудников

Telegram не поддерживает «меню для списка ID», но поддерживает команды для конкретного
чата, поэтому в `bot/commands.py` меню ставится персонально:

| Кому | Что видно в меню |
|---|---|
| Обычный пользователь | `/start`, `/audit`, `/help`, `/reset` |
| Менеджер (`MANAGER_CHAT_IDS`) | + `/history`, `/id` |
| Админ (`ADMIN_IDS`) | + `/stats`, `/leads`, `/knowledge`, `/test_notify` |

- Если менеджер ещё ни разу не открывал бота, Telegram не даст поставить ему меню —
  оно применится автоматически при первом `/start` (см. `bot/handlers/start.py`).
- При удалении ID из `.env` персональное меню сбрасывается при следующем запуске
  (используется таблица `kv`); сами команды всё равно защищены проверкой доступа.
- В группе из `MANAGER_CHAT_IDS` меню видят все её участники — это доверенный чат.
- `/help` дополняется блоком команд только для сотрудников.

## Что осознанно оставлено заготовкой

- **Получатели уведомлений** — только через `.env` (никаких захардкоженных ID).
- **FSM и история диалога** — в памяти: после рестарта активные заявки и контекст
  сбрасываются. Для продакшена — RedisStorage (aiogram) и хранение истории в Redis.
- **Поиск** — индекс в памяти, SQLite-хранилище. На десятки тысяч чанков стоит перейти
  на pgvector / Qdrant / FAISS.
- **Интеграция с CRM** — точка расширения: `ManagerNotifier.notify` (webhook/amoCRM/Bitrix).
- **Согласие на обработку ПДн** — в тексте заявки есть ссылка на политику; отдельного
  чекбокса согласия нет.
- **Аналитика** — только собственные события в SQLite, без внешних систем.
- **Локализация** — только русский.

## Частые проблемы

- **«Не удалось отправить уведомление»** — менеджер ещё не нажал `/start` у бота
  (бот не может писать первым), либо неверный ID/группа.
- **Бот отвечает выдержками** — не задан `LLM_API_KEY` или провайдер вернул ошибку
  (смотрите логи, там будет HTTP-код).
- **«База знаний пуста»** — не выполнен `python -m bot.rag.ingest`.
- **Ответы не по теме** — увеличьте `RAG_TOP_K`, снизьте `RAG_MIN_SCORE` или
  переиндексируйте сайт после правок, затем проверьте чанки через `/knowledge`.
- **Windows + PostgreSQL/таймзоны** — в проекте используется фиксированная MSK (UTC+3),
  внешний tzdata не нужен.
